Skill feedback (you asked for improvements)

Both skills loaded fine. They were written for the FirmaTask iOS app, and that shows when they're applied to a website:

  1. They're not installed as skills. They live in 0_archive/TaskApp_UiTest/DesignReferences/, so they only load when attached by hand. Move them to ~/.claude/skills/ (or a plugin) so they trigger automatically.
  2. Apple HIG skill is hard-wired to FirmaTask. The "Project context: FirmaTask" section, hacker-theme overrides and SwiftUI checks should move into a project-specific file. The core skill should be platform-neutral.
  3. Neither has a "web and marketing site" mode. Add a short reference that translates each principle for the web: 44pt targets become 44 CSS px, Dynamic Type becomes rem and clamp() type, Reduce Motion becomes prefers-reduced-motion, and system components become semantic HTML plus ARIA patterns (disclosure menu, dialog).
  4. Material skill tells you to generate color from a seed and always ship dark mode. For branded work that conflicts with fixed brand palettes. Add a "brand-locked" path: map existing brand colors onto M3 roles, and verify on-* contrast manually.
  5. Material skill tells you to prefer Material Web components. That doesn't apply to Elementor or WordPress. Add a note: "when the platform is a CMS or page builder, apply the tokens and principles, not the components."
  6. Both lack a verification script. A small Playwright checklist (overflow, heading order, target sizes, contrast of computed pairs, focus visibility) would make "verify before handoff" repeatable. The ones used here are saved in tools/ (verify.js, shot.js, cap.js; they need npm i playwright).
